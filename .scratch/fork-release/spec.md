# 定制版同步与便携测试版发布规格

## Problem Statement

维护者需要让定制版持续跟踪上游开发，又能从自己的 Windows 环境可靠分发小范围便携测试版。

## Solution

每天检查上游开发分支，候选合并通过轻量门禁后自动合并；维护者主动运行本机命令，从已推送提交构建、验证并直接公开带有独立版本标识的 GitHub Pre-release。

## User Stories

1. 作为维护者，我希望上游无变化时不产生空 PR。
2. 作为维护者，我希望重复检查更新同一个同步 PR。
3. 作为维护者，我希望只在确切候选合并结果通过门禁后合并。
4. 作为维护者，我希望上游改写历史、冲突或检查失败时停止自动合并。
5. 作为维护者，我希望合并前分支变动使旧检查失效。
6. 作为维护者，我希望同步使用仅限本 fork 的 GitHub App 短期令牌。
7. 作为维护者，我希望不向验证候选代码的任务暴露写入凭据。
8. 作为维护者，我希望复用 E 盘依赖与缓存而不引入云端完整构建。
9. 作为维护者，我希望发布只接受已推送的确定源码提交。
10. 作为维护者，我希望未提交改动、错误提交或程序运行中使发布停止。
11. 作为维护者，我希望编译、真实布局回归及包内容校验全部通过后才公开。
12. 作为使用者，我希望便携包不含维护者的账号、日志或缓存。
13. 作为使用者，我希望下载包附有校验值和对应源码信息。
14. 作为维护者，我希望上传中断不留下公开但缺件的版本，重试不覆盖既有发行。
15. 作为使用者，我希望手动下载入口指向定制版，而非覆盖自有功能的上游发行。

## Implementation Decisions

- 上游是 AyuGram/AyuGramDesktop:dev；定制分支是 jinmo100/AyuGramDesktop:dev；镜像分支为 upstream-sync，保留普通 merge 历史。
- 同步准入包括合并无冲突、笔记门禁、Actions 语法校验、四组独立逻辑测试；生产 Windows 行为不由这些检查保证。
- 检查执行与持有写入凭据的操作分离；验证结果绑定目标和来源两个 SHA，合并前再次核对。失败通过工作流与 PR 留痕，GitHub 通知依赖用户订阅设置。
- 发布为 Windows x64 Debug 便携测试版，分发名称 AyuGram-Jinmo，版本为上游基础版本加 jinmo 发行序号。
- 发布源码必须干净、与指定已推送提交一致，相关子模块必须匹配。外部依赖复用，但来源与配置记录在元数据中。
- 使用草稿暂存上传，完整校验后自动公开 Pre-release；已有公开发行不覆盖，失败可用相同身份恢复。
- 内置自动更新通过构建选项关闭，手动下载链接可配置为本 fork Releases；保持程序名称图标。
- 凭据由 GitHub App 和本机 GitHub CLI 管理，不写入脚本、包或日志。

## Testing Decisions

- 沿用访谈确认的入口：同步候选检查和本机发布命令。用临时真实 Git 仓库验证无变化、冲突、改写历史、分支移动与干净度。
- GitHub 是外部系统边界，可以用模拟 HTTP 服务或进程接口验证 PR/Release 行为，不模拟内部业务逻辑。
- 测试包内容白名单、校验值、版本选择、失败不公开和重试身份；Windows 编译/布局检查必须由发布适配器实际调用，测试不把模拟编译当作实机验证。
- 不在当前用户测试进程运行时构建或关闭应用；本轮自动化实现用确定性脚本测试及 PowerShell 解析检查验证。

## Out of Scope

云端完整构建、self-hosted runner、Release 优化构建、安装器、独立更新签名服务、程序全面改名、自动处理冲突、自动提交用户改动。
